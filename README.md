# P2PStream

Плагин P2P-стриминга для **Vesktop** (через [veskforge](https://github.com/Microck/veskforge)) — замена Discord Go Live без лимитов Discord:

- до **100 Мбит/с** видео (Discord даёт ~8), разрешение до 4K, до **240 FPS**
- задержка **30–80 мс** в mesh-сети до 5 зрителей (WebRTC P2P, без сервера)
- кодеки: **AV1 / VP9 / H.264** (автовыбор), стерео-звук Opus до 512 кбит/с
- **нативный пикер трансляции** в стиле Discord: сетка источников с превью, живой предпросмотр, качество (как «Stream Mode»), звук — и выбор «P2P» или «Обычный стрим Discord»
- **плитка стрима в звонке как у обычного Go Live**: LIVE, метка **P2P**, качество (например 1080p60), живое превью, кнопка «Смотреть» открывает P2P-просмотр
- окно просмотра: зум к курсору, **PiP**, фуллскрин, статистика (битрейт/FPS/задержка)
- **невидимый сигналинг** — служебные сообщения в чате канала живут ~2.5 сек и удаляются сами
- команды `/p2p-start`, `/p2p-stop`, `/p2p-watch`

## Установка (veskforge)

1. Установи [veskforge](https://github.com/Microck/veskforge) (нужны Git и Node.js LTS).
2. В veskforge добавь плагин источником **Git**:
   ```
   https://github.com/shxtai/P2PStream
   ```
   (veskforge принимает только HTTPS-ссылки на корень репозитория)
3. Нажми **Build** — veskforge сама клонирует Vencord, вставит плагин в `src/userplugins` и соберёт dist.
4. Нажми **Apply / Launch** — Vesktop переключится на эту сборку.
5. В настройках Vencord: **Plugins → P2PStream → Enable**.

Плагин нужно поставить **обоим**: и стримеру, и зрителям.

### Обновление

Просто нажми **Build** в veskforge ещё раз — она сама делает `git fetch` из репозитория и пересобирает плагин последней версии. Обновления Vencord плагин не ломают: veskforge пересоздаёт `src/userplugins` из своего манифеста при каждой сборке.

### Установка без репозитория (локально)

- **Папкой**: скачай папку с файлами плагина и добавь её в veskforge источником *Local folder* (внутри должен быть `index.tsx`).
- **Одним файлом**: возьми `P2PStream.tsx` из релизов и добавь как *Local file* (файл обязан оканчиваться на `.ts`, `.tsx`, `.js` или `.jsx`).

## Как стримить

1. Подключись к голосовому каналу и нажми кнопку **«Демонстрация экрана»** — откроется пикер P2PStream (окно выбора стрима Discord подменяется целиком):
   - сверху — **сетка источников** (экраны и окна с превью) — клик выбирает источник и сразу запускает живой предпросмотр;
   - **Качество** — разрешение (480p–4K/родное) и FPS (15–240) рядами, как в новых сборках Discord;
   - **Режим** — «Игры» (плавное движение) / «Кино» (чёткая картинка) — это настоящий `contentHint`, тот же, что использует Discord;
   - переключатель **звука**, «Дополнительные настройки» — кодек и битрейт;
   - зелёная кнопка — **Начать P2P-трансляцию**, рядом — **«Обычный стрим Discord»** (дефолтный Go Live; если источник уже выбран, лишний пикер не показывается).
2. Зрители видят твой эфир **прямо в звонке** как обычный стрим (плитка с LIVE и меткой P2P). Превью на плитке живое: у зрителей кадры приходят по P2P-каналу ещё **до** подключения к просмотру. Клик по плитке открывает просмотр; пилюли внизу экрана и `/p2p-watch` тоже работают.

> До 240 FPS стабильнее всего при захвате **всего экрана**: окна обновляются только при перерисовке, так что статичное окно может выдавать меньше кадров.

### Про звук

- Захватывается **системный звук** (Windows: WASAPI loopback) — то есть весь звук ПК.
- Честно про ограничение текущей версии: в прямом захвате (getUserMedia loopback) звуки **самого Discord** тоже попадают в эфир. Полноценный вариант «весь звук, кроме Discord» и «звук только одного приложения» — это нативный хелпер на WASAPI Process Loopback (так делает сам Discord); он запланирован на **v1.4**. Пока: выключи звуки уведомлений Discord на время стрима или выбери «Без звука».

### Профили Игры / Кино

- **Игры** — 1080p60, битрейт 30 Мбит/с, буфер 0 мс, оптимизация движения (минимальная задержка);
- **Кино** — 1080p60, битрейт 20 Мбит/с, буфер 150 мс, оптимизация детализации.

Профиль переключается на живом эфире: кнопками в панели внизу экрана или в пикере — FPS/разрешение/битрейт/контент применяются **на лету**, без перезапуска стрима.

## Настройки

- Режим кнопки «Демонстрация экрана»: свой пикер (P2P или обычный стрим) / буст Go Live / без изменений
- **Показывать P2P-эфир в звонке как обычный стрим** (плитка с превью) — можно выключить, если что-то не так
- Разрешение 720p–4K/родное; FPS 30–240; видеобитрейт до 100 Мбит/с; аудио до 512 кбит/с (стерео)
- Кодек: Авто (H.264 → VP9 → AV1) / ручной
- Буфер зрителя 0–500 мс (0 = минимальная задержка)
- STUN (по умолчанию Google) и TURN — только если P2P не пробивает NAT

## Совместимость

Формат — стандартный Vencord userplugin (`index.tsx` + файлы рядом), поэтому плагин также ставится обычным путём: клон [Vencord](https://github.com/Vendicated/Vencord) → `src/userplugins/P2PStream` → `pnpm build` → `pnpm inject`.

## Версии

- **1.3** — пикер v2: подмена окна выбора стрима через перехват `getDisplayMedia` (устойчиво к переименованиям модулей Discord — старые хуки `openShareModal`/`setGoLiveSource` больше не нужны), собственная сетка источников с превью через main-процесс Vesktop (без двойных пикеров), живое превью плитки у хоста и у зрителей **до** подключения (кадры по DataChannel), радио-ряды качества как в новых сборках Discord, режим Игры/Кино на настоящем `contentHint`, «Обычный стрим» без лишних окон.
- **1.2** — нативная интеграция: свой пикер трансляции в стиле Discord с выбором «P2P или обычный стрим», плитка P2P-эфира в звонке (LIVE, превью, зрители), FPS до 240, живое применение профилей Игры/Кино, селектор звука (системный без Discord / без звука).
- **1.1** — фикс краша main-процесса (`Cannot find module '~plugins'`): файл хуков переименован `native.ts` → `hooks.ts`, чтобы Vencord не включал рендер-код в main-бандл.
- **1.0** — первый релиз: P2P mesh до 5 зрителей, профили качества, невидимый сигналинг, зум/PiP у зрителя.
