# P2PStream — внутренняя документация

Плагин P2P-стриминга для Vesktop/Vencord: замена Discord Go Live без лимитов Discord. WebRTC mesh до 5 зрителей, до 100 Мбит/с, до 240 FPS, AV1/VP9/H.264, стерео Opus до 512 кбит/с. Установка и пользовательские инструкции — в [README.md](README.md), здесь — как оно устроено и полный разбор проблем.

---

## Как работает (кратко)

```
хост                              зритель
[захват экрана/окна]              [плитка стрима в звонке / пилюля / /p2p-watch]
  + звук (WASAPI loopback)            |
        |                         ViewerModal / MiniPlayer / PiP
        v                             ^
[WebRTC mesh, до 5 peer'ов] <=========+
        ^
        | сигналы (announce/join/offer/answer/ice)
[сигналинг: тихий Discord-транспорт или MQTT-брокер]
```

- **engine.ts** — сессии хоста/зрителя, mesh, кодеки (`setCodecPreferences`, порядок Авто: H.264 → VP9 → AV1), битрейт/FPS через `setParameters`, jitter buffer, статистика.
- **capture.ts** — прямой захват `getUserMedia(chromeMediaSource=desktop)` мимо чужих пикеров, живое применение FPS/разрешения.
- **hooks.ts** — перехват `getDisplayMedia` (устойчив к переименованиям модулей, re-assert каждые 3 с), перехват кликов по кнопке «Стримить», перехват Go Live (`MEDIA_ENGINE_SET_GO_LIVE_SOURCE`).
- **nativeTiles.ts** — показывает P2P-эфир в звонке как обычный стрим: фейковые `ApplicationStream`/участники через Proxy, обёртки трёх сторов, превью — кадры со скрытого `<video>` через canvas.
- **signaling.ts / broker.ts** — транспорт сигналов (см. ниже). Формат сигнала: конверт `{v:1, t, s, from, to?, ch?, av?, d | (e+pk)}`, типы: `announce / bye / join / offer / answer / ice / leave / query`; payload сжат deflate+base64url, с фрагментацией.
- **native.ts** (main-процесс) — `desktopCapturer` для сетки источников + запуск хелпера звука.
- **native/p2paudio.c** — WASAPI Process Loopback (~тот же механизм, что у Discord): окно → звук приложения, экран → вся система без Discord. PCM float32 48 kHz stereo по stdout → AudioWorklet → дорожка в WebRTC. Встроен в native.ts base64, распаковывается в `%APPDATA%\vesktop\p2pstream\`.
- **cf-worker/** — свой MQTT-брокер (подмножество MQTT 3.1.1 на Durable Objects) — сигналинг целиком мимо Discord.
- **ui/** — SharePicker (пикер в стиле Discord), ViewerModal (зум к курсору, PiP, фуллскрин, статы), MiniPlayer (перетаскиваемая панель, не рвёт эфир), Bars (пилюли LIVE + хост-панель), AboutCard.

**Сигналинг** (порядок попыток): MQTT-брокер (если включён) → **тихий Discord-транспорт** (по умолчанию): адресные сигналы в ЛС с пиром, broadcast в голосовой канал, всё через REST с флагом `@silent` (SUPPRESS_NOTIFICATIONS) и самоудалением ~2 с; SDP/ICE запечатаны ECDH P-256 + AES-GCM. Видимые коды в чате — последний фолбэк.

## Проблемы

### Текущие известные (не исправлены / по дизайну)

| # | Проблема | Причина | Обход |
|---|----------|---------|-------|
| 1 | **Публичные MQTT-брокеры молча режутся DPI**: WSS открывается, CONNECT дропается без CONNACK (emqx/hivemq/mosquitto — все три). Не сеть виновата и не баг пакета — пакет проверен побайтово | DPI-фильтрация бинарных WSS-кадров к известным публичным брокерам | Брокер с v1.9 выключен по умолчанию; дефолт — тихий Discord-транспорт. Хочешь совсем без Discord — свой брокер: `cf-worker/worker.js` (2 мин на Cloudflare) или mosquitto на своём сервере с `protocol websockets` |
| 2 | **240 FPS стабильно только на захвате всего экрана** | Окна перерисовываются только при изменении контента — статичное окно физически не даёт кадров | Стрими экран; для окон 60–90 FPS |
| 3 | **Звук UWP-приложений из Магазина может не захватываться** (умный звук) | Процессы UWP живут вне окна — ограничение Windows WASAPI Process Loopback | Ничего; авто-фолбэк на системный звук |
| 4 | **Нативный игровой оверлей Discord недоступен** поверх нашего потока | Оверлей рисуется только для потоков самого Discord | Панель хоста плагина (пилюли/бары) |
| 5 | **Однофайловая сборка (`P2PStream.tsx`) без native-части** | veskforge-режим «Local file» не переносит main-процесс | Ставить репозиторием Git-источником или папкой — тогда сетка источников через `desktopCapturer` и умный звук работают |
| 6 | **Аварийный TURN (openrelay) медленный** — трафик через чужой сервер | Это ретранслятор, а не прямое соединение | Включается только если прямое P2P не собралось; свой TURN в настройках отключает его |
| 7 | **Динамический IP на своём брокере (нетбук/домашний сервер)** | Адрес в настройках фиксированный | DDNS, либо Cloudflare Worker (статический `*.workers.dev`, бесплатно) — рекомендовано |
| 8 | **Шифрование чат-сигналов только между v1.10+** | Гейтинг по версии пира (старые версии не умеют `e`) | Обновиться обоим; брокерные пиры шифруются всегда (v1.7+) |
| 9 | В Vencord-сборках **без main-части** (старый инжект) пикер живёт веб-фолбэком `getDisplayMedia` | Нет IPC `desktopCapturer` | Git-источник / папка / VencForge |

### Диагностика: `/p2p-doctor`

Всё валит в консоль (F12): версия, клиент, voice-канал, режим кнопки, перехваты (`getDisplayMedia` / Go Live / клик), **native-каналы** (если «НЕТ» — однофайловая сборка), кодеки, здоровье сигналинга (успешно/ошибок подряд + последняя ошибка), статус брокера (выключен / подключён / включён-не-подключён + причина), статус тихого транспорта.

Типичные строки для проверки соединения:

- в консоли зрителя: `ICE [...]: host=…, srflx=…, relay=…` — **relay-кандидаты есть всегда** (аварийный TURN), соединение обязано собраться даже за симметричным NAT/CGNAT;
- STUN должен показывать Cloudflare (в старых сохранённых настройках мог остаться дефолт без него — v1.9 доливает сам);
- брокер «не подключён (нет CONNACK)» = пункт 1 таблицы, это DPI, не баг плагина.

### Симптом → действие

| Симптом | Действие |
|---------|----------|
| Зритель «не грузит» эфир | `/p2p-doctor` у обоих: строки `зритель …`/`просмотр …` (conn/ice/sig, «оффер НЕ получен»), в консоли `→ offer`/`← offer` и предупреждения «Не удалось распечатать»; оба должны быть на v1.11+ |
| В чате мелькают коды | Тихий транспорт выключен или REST-отправка упала: `/p2p-doctor` → «тихий Discord-транспорт»; проверить `silentDm` и `chatFallback` в настройках |

| Кнопка «Полноэкранный режим» на обычном Discord-стриме открывала пикер | Исправлено в v1.10 (регулярка + структурная защита плиток с видео) — обновиться |
| Сетка источников пустая / «Error processing argument» | Был фикс v1.5.1; если повторяется — сборка без native-части, см. п. 5 |

## Справочник (кратко)

**Команды**: `/p2p-start`, `/p2p-stop`, `/p2p-watch`, `/p2p-doctor`.

**Основные настройки**: режим кнопки (свой пикер / буст / off) · профиль Игры (1080p60, 30 Мбит/с, буфер 0, motion) / Кино (1080p60, 20 Мбит/с, буфер 150, detail) / Вручную · разрешение 720p–4K/родное · FPS 30–240 · видео 2–100 Мбит/с · аудио Opus 64–512 кбит/с · кодек Авто/H.264/VP9/AV1 · буфер зрителя 0–500 мс · звук: Умный (приложение/система без Discord) / системный / off · `silentDm` (тихий транспорт, вкл) · `chatFallback` (вкл) · `brokerEnabled` (выкл) + `brokerUrl` · `emergencyTurn` (вкл) · свой TURN · `nativeTiles` (вкл) · `autoWatch` · `notifyLive` · `discoverPings` · `showStats`.

**Совместимость**: Windows 10 2004+ для умного звука; плагин нужен **обоим** (стримеру и зрителю); однофайловая сборка — без умного звука и без сетки источников.

## Сборка

Клон Vencord → `src/userplugins/P2PStream` (эта папка) → `pnpm i` → `pnpm build`; проверки: `pnpm lint`, `npx tsc --noEmit`. Нативный звук: `native/build.sh` (zig cc или mingw-w64) — пересобирает `p2paudio.exe` и вшивает в `native.ts`. CF Worker: см. шапку `cf-worker/worker.js` (дашборд) или `cf-worker/wrangler.toml` (CLI).
